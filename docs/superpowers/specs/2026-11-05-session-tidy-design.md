# AI 梳理会话与共同经验

状态：设计待确认，尚未实现。对应 Trace Canvas 待办 `cmw2w4beayid9i`。

## 用户要解决的事

会话分散在不同机器、目录和线路，重复开展的工作越来越多。一次 AI 梳理应当能发现相关会话、留下共同经验，并把暂时不用的会话收起来，减少画布干扰。用户同时关心 token 开销。

## 已有能力与依据

- `app/index.html` 的 `buildAIPrompt()` 目前只提供线路目标、最近记录标题和待办；建议合并线路、收尾、勾选待办，每条由用户应用并可撤销。
- `src/ops.mjs` 的 `sessionList()` 已合并会话绑定表和记录中的会话，保留机器、线路、标题、最后活动时间、恢复命令。
- 跨机器数据通过 `src/sync.mjs` 同步；远端运行状态另由 `src/remote.mjs` 按现有开关读取。此功能不增加远程全文扫描。
- `/api/bind` 已能把会话绑定到现有线路；绑定影响后续记录，历史记录保留原有出处。
- `src/lessons.mjs` 已支持从决定、收尾总结提炼经验，再由用户勾选写入 Theatrum。
- 本次只读盘点：48 条线、99 个会话，会话元数据约 18,913 字符；这不是 tokenizer 测量，也不包含线路与提示词。

## 首版完整行为

### 1. 会话摘要加入同一次梳理

沿用「更多 → AI 梳理」。把会话表和实时栏按会话 ID 合并去重，包含本机及已同步机器的已知会话。每项只提供 ID、agent、机器、线路、短标题、最后活动时间和运行状态，不提供完整对话、恢复命令或目录全文。

沿用线路目标、最近记录、未完成待办；为经验候选补充有限的决定和收尾总结，并保留记录 ID。默认以全局工作区为范围，忽略已经归档的项目和会话。

设置明确输入上限，逐项装入完整 JSON 对象，不能在 JSON 中间截断。设计默认值为最多 100 个会话、数据区合计最多 64,000 字符；提示词另计。优先保留正在运行的会话、各线路的最近会话，再填入闲置会话。页面显示本轮会话/线路覆盖数及省略数；有省略时不声称读完所有会话。此数字是输入大小限制，不承诺精确 token 或费用。

### 2. 同一工作的会话归线建议

新增「会话归线」建议：给出会话、目标现有线路和依据。用户逐条点击后调用现有绑定能力；返回后再刷新列表，可撤销到先前绑定。绑定前检查会话和目标线路仍存在，目标不是已归档或已合并线路。

若重复的是两条线路，继续使用已有合并建议。AI 返回对象只包含已提供的 ID，前端与服务端均验证引用。标题相似本身不足以判断重复，无法确认时不建议。归线不会移动历史记录、合并对话文件或关闭任何终端。

### 3. 可恢复的会话归档

归档是会话表上的可选标记，不删除会话、线路、记录或对话文件。归档后，会话从实时栏、agent 图和线路默认会话列表中隐藏，并退出自动分派候选。线路上的记录仍保留，因此若还需要收起线路，继续使用已有收尾/合并功能。

在线路的会话区保留「已归档 N 个」入口，可展开查看、恢复和使用原恢复命令。AI 结果里刚应用的归档也可撤销。空线路不因归档会话被自动删除。

正在工作、等待用户回复及参与当前 Autopilot 的会话不允许归档。远端实时状态不可确认时，不应用该远端会话的 AI 归档建议；明确提示先确认该机器状态。闲置 7 天仅为 AI 建议依据，不是定时归档规则。上述阈值是实现默认值，不是用户已同意的偏好。

归档后收到新的用户指令或实际运行活动，应恢复可见并重新进入分派候选。使用现有数据锁更新字段，不覆盖并发绑定/活动字段。同步仍走既有会话文档机制，测试远端归档、恢复及新活动后的结果。

### 4. 提炼共同经验

同一次 AI 回答增加经验候选：标题、适用条件及原因、来源记录 ID、相关会话 ID。仅根据已提供的决定、收尾总结提炼；不能把会话标题猜成经验，也不能把未解决的分歧写成共同结论。

页面展示来源，让用户勾选并点击「记住勾选的」。复用 `rememberLesson()` 写入 Theatrum。每项保存成功后再显示成功并写入可追溯的画布结果；失败项保留重试，不把失败项记成已保存。相同来源和相同内容已经保存时，不在下一轮重复建议。跨项目经验默认沿用已有长期经验类型，并清楚展示保存目的地。

## 必须覆盖的代码与调用方

- `app/index.html`：中英文字、摘要预算与覆盖提示、建议验证/显示/应用/撤销、归档入口；实时栏、agent 图、线路会话列表一致过滤。
- `src/ops.mjs`：会话输出附归档状态；分派候选过滤，同时保留恢复、历史阅读和复盘需要的完整会话列表。
- `src/server.mjs`：归档/恢复的窄接口及引用与实时状态验证；共同经验保存的来源验证和成功结果记录。保留现有本机 AI/记忆写入限制及请求头检查。
- `src/hook.mjs`：实际新活动后的会话恢复，保留已有绑定与恢复命令。
- `src/sync.mjs`：优先不改协议，新增会话字段走既有同步；用测试确认恢复状态与活动更新的交互。
- `src/lessons.mjs`：复用写入函数，只有确实不能复用的来源处理才做最小扩展。
- 对应 `test/` 测试、README 中英说明、CHANGELOG；使用虚构数据完成 UI 验证与演示素材，不使用真实会话内容录制。

## 验证标准

1. 同一会话从会话表、记录和实时栏出现时只发给 AI 一次；包含不同机器；预算内 JSON 完整且覆盖数准确；不读取 transcript。
2. AI 返回未知 ID、重复建议或无效来源时拒绝应用；正在工作/等待回复的会话和状态不明的远端会话受到保护。
3. 归档与撤销后各视图和自动分派一致，原记录与恢复命令可用；新活动使会话重新出现；同步往返不丢其他字段。
4. 归线、撤销和既有线路合并保持原行为；历史记录不被静默移动。
5. 经验必须勾选后保存；验证部分失败、成功出处及重复保存处理；使用假的 AI/Theatrum 执行器测试，不在自动测试中调用真实 AI 或记忆。
6. 运行现有完整测试；用独立临时数据目录验证中英文、桌面和窄屏，禁止开发实例以正式机器名同步。

## 本次不做

不做后台定时扫描、定时归档、自动删除、自动合并、全文向量检索、摘要缓存系统、新模型依赖或精确费用估算。没有同步到画布的外部会话仍由既有导入功能处理。本次也不执行用户真实会话的归档、归线或记忆写入。
