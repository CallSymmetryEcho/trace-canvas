# Autopilot 怎样从自己的决策数据里学习（调研）

2026-11-05。由 Haiku 子 agent 检索整理，Autopilot 线（待办 cmw30jitj17tpm）。论文结论大多来自搜索摘要，只有 4 篇打开了摘要页核对（见文末）；未核实的数字已标注，引用前请看原文。

## 当时手上的数据

- 239 条决定，其中 56 条写明了依据的规则（H1、R5 这类）。
- 411 条待办，320 条做完。
- 复核刚开始：16 条等复核，1 条被退回。
- 7 个 Question 和用户的回答，18 条 Autopilot 小结。
- 会话完整记录（transcript）。

主模型是 Claude、Codex 这类闭源 API，改不了它们的权重；必要时可以训练一个小模型或分类器。

## 排名（最适合我们的在前）

### 1. 检索先例 + 从记录里提炼经验（不改权重）——适配度：高

- **做法**：每条决定存成一个「先例」，包括情境、依据的规则、结果、复核是通过还是退回，以及用户对问题的回答。做新决定时，取最相近的 k 条，连同「这类情况人当时怎么判的」一起放进提示词。定期让模型从成功和失败的记录里归纳几句自然语言经验，作为规则的补充。
- **来源**：
  - ExpeL: LLM Agents Are Experiential Learners, 2023（AAAI-24），https://arxiv.org/abs/2308.10144 （已核实摘要）。
  - Memento: Fine-tuning LLM Agents without Fine-tuning LLMs, 2025，https://arxiv.org/abs/2508.16153 。摘要片段称在分布外任务上提升 4.7–9.6 个百分点，未核实。
  - Reflexion, 2023（NeurIPS），https://arxiv.org/abs/2303.11366 。
- **数据**：几十到几百条带标签的先例就够用，现有的约 240 条够做第一版。
- **为什么适合**：只用 API 就能做，数据量也对得上，正好对着「决定的依据说得含糊」这个问题。
- **和现有功能的关系**：我们已经有一半了。0909af5 做了「归档项目提炼经验 → 新线开工时带入 → Autopilot 拿不准时先查」，只是现在查的是经验和归档线，还没查同类的过往决定，也没查用户的回答。

### 2. 用复核结果当指标，优化提示词和规则——适配度：中高

- **做法**：把规则清单和提示词当成可以调的参数，用「通过 / 退回」和用户的回答当分数，让模型读失败的记录、反思、改写规则。
- **来源**：
  - GEPA, 2025（ICLR 2026），https://arxiv.org/abs/2507.19457 （已核实摘要）。摘要称比 GRPO 平均高 6%、最多高 20%，rollout 最多少 35 倍；各版本数字有出入。
  - DSPy, 2023，https://arxiv.org/abs/2310.03714 。
  - OPRO, 2023，https://arxiv.org/abs/2309.03409 。
  - TextGrad, 2024（2025 年发在 Nature），https://arxiv.org/abs/2406.07496 。
- **卡在哪**：复核结果目前只有十几条，做不了可靠的评估集。等复核数据攒到几百条再上。

### 3. 「问还是做」小分类器 / 选择性预测——适配度：高（专治问多了或问少了）

- **做法**：输入是决定的情境、命中了几条规则、规则之间有没有冲突、检索到的先例；输出是三选一：规则能直接判、应该问、先做再请人确认。训练标签来自用户的回答：回答和规则推出来的一样，说明本不该问；回答里带了新信息，说明该问。
- **来源**：
  - Ambig-SWE / Interactive Agents to Overcome Underspecificity, 2025，https://arxiv.org/abs/2502.13069 （已核实摘要）。模型难以分辨指令说清了没有；允许交互时，最高提升 74%。
  - Ask or Assume? Uncertainty-Aware Clarification-Seeking in Coding Agents, 2026，https://arxiv.org/abs/2603.26233 （已核实摘要）。把「判断有没有说清」和「执行」分开，简单任务少问，复杂任务多问。
  - Conformal Abstention, 2025，https://arxiv.org/abs/2502.06884 ；CLARITI, 2026，https://arxiv.org/abs/2604.14624 （这两篇只看到搜索摘要）。
- **数据**：几十到一两百条「问 / 不问 + 用户回答」就能训一个简单分类器。现在只有 7 个问题，要先攒数据。

### 4. 用失败案例修订规则（宪法式）——适配度：中

- **做法**：把复核里反复出现的失败模式归纳成「规则修改建议」，经人审阅后并进决策画像。不让模型直接改规则。
- **来源**：Constitutional AI, 2022，https://arxiv.org/abs/2212.08073 。
- **说明**：成本低，和第 2 条可以合在一起做。

### 5. 工作流 / 技能库——适配度：中

- **做法**：从做成功的待办里归纳常用流程，存起来供以后检索。
- **来源**：Agent Workflow Memory, 2024，https://arxiv.org/pdf/2409.07429 ；Voyager, 2023，https://arxiv.org/abs/2305.16291 。
- **说明**：对「流程一致」有用，对「判断边界」帮助不大。

### 6. 过程奖励模型——适配度：低到中

- **来源**：A Survey of Process Reward Models, 2025，https://arxiv.org/abs/2510.08049 。
- **说明**：要每一步都有标签，我们没有。可以压缩成一个 LLM 审查员，只查「引用的规则是不是真的适用」（这一点是推断，没有来源）。

### 7. 离线强化学习 / DPO——适配度：现在低

- **来源**：
  - DPO, https://arxiv.org/abs/2305.18290
  - ArCHer, https://arxiv.org/abs/2402.19446
  - Agent Q, https://arxiv.org/abs/2408.07199
  - DigiRL, https://arxiv.org/abs/2406.11896
  - WebRL, https://arxiv.org/abs/2411.02337
- **为什么现在不做**：这类方法要几千条轨迹，还要能训练的开源模型。我们只有几百条，主模型也改不了。等将来训练小模型时，复核的「通过 / 退回」可以作为偏好对的起点。

## 结论（Autopilot 线的判断）

1. **先做第 1 条**，在现有的「拿不准先查经验」上扩一步：也查同一条线和同类线上的过往决定、Question 以及用户的回答，把最相近的几条和「当时人怎么判的」带给 agent。不训练，不加依赖。
2. **同时开始攒数据**：每个 Question 和它的回答、每次退回都已经记在画布上；再加一个按需导出的脚本，整理成 {情境, 规则, 动作, 结果}。第 3 条（问 / 做分类器）和第 2 条（规则优化）等数据到几百条再做。
3. **强化学习暂不做**：数据和模型条件都不满足。

## 第一个实验（报告给出的方案，阈值是报告自己定的，没有来源）

- **准备数据**：把约 240 条决定整理成 {情境摘要, 依据规则或空, 动作（做 / 问 / 停）, 复核结果, 用户回答}。
- **两组对比**：
  - 基线：当前提示词，不检索；
  - 方案 A：每次决定时检索 k=5 条最相近的先例，连同人当时的判断放进提示词。
- **衡量**：
  - 不必要的提问率；
  - 漏问率；
  - 被退回的比例；
  - 因为一条卡住而整轮停下的次数；
  - 引用的规则和人判断时用的规则是否一致。
- **成功标准**：在留出的 50 条上，不必要提问少 30% 以上，漏问率和退回率不上升。样本少，结论只能当方向参考。
